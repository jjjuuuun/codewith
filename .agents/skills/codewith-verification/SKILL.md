# 검증과 실행

모든 명령은 `codewith/` 기준이다. 포트·실행 방식은 환경 설정과 현재 프로세스를 확인한다.

## 변경에 맞는 검사

| 변경                       | 기본 검사                                                        |
| -------------------------- | ---------------------------------------------------------------- |
| 지침·문서만 변경           | 경로·링크·내용·형식 확인. 앱 전체 테스트는 보통 불필요           |
| JS/Vue 구현                | `npm run check`, `npm run build`, 영향을 받는 테스트             |
| UI·라우팅·폼·테마          | 실제 화면 확인과 관련 브라우저 검사                              |
| 서버·데이터·인증·공유 규칙 | 관련 `node --test tests/<name>.test.mjs`; 공통 영향은 `npm test` |

- `npm test`와 `npm run test:browser`는 먼저 빌드한다. 이미 빌드했고 소스가 그대로라면 `node verify_browser.mjs`로 운영 브라우저 검사만 실행할 수 있다.
- 개발 모드 브라우저 검사는 `npm run test:browser:dev`다. 라우팅·Vite 연결을 바꾸면 운영/개발 양쪽을 확인한다.
- 작은 문구·아이콘 변경마다 전체 테스트를 반복하거나 구현을 그대로 복제한 테스트를 만들지 않는다. 동작 위험과 실패 증거에 맞춰 검사 범위를 정한다.
- 브라우저 테스트는 임시 저장소와 테스트 AI 공급자를 사용한다. `.codewith/` 실제 계정/문서를 테스트 데이터로 쓰지 않는다. Chromium 경로는 `CODING_CHROMIUM`으로 설정할 수 있다.
- 운영 브라우저 검사 중에는 `dist/`를 다시 빌드하지 않는다. 해시가 달라지면 진행 중인 검사의 자산 요청이 실패할 수 있다.

포맷 기준은 `npm run format:check`로 검사한다. 포맷 검사는 Vue 의미 규칙·문법·동작 검증을 대체하지 않는다.

## 재현과 진단

1. 실제 오류 주소·HTTP 응답·브라우저 콘솔 또는 스크린샷으로 증상을 구분한다. 과거 테스트 성공만으로 사용자 오류를 부정하지 않는다.
2. `npm run dev`는 Vue/CSS HMR을 제공하지만 서버와 공유 서버 라우트는 프로세스에 남는다. `npm start`도 자동 재시작하지 않는다.
3. 링크가 새 주소인데 실행 중인 서버만 404를 반환하면 서버 시작 시각과 최신 코드를 비교한다. 테스트 서버가 새 코드로 통과해도 사용자 서버는 이전 모듈을 실행할 수 있다.
4. 재시작이 필요하면 해당 CodeWith 인스턴스와 실행 옵션을 확인한다. 세션에서 허용된 범위 안에서 처리하며, 불명확하면 재시작 필요성을 설명한다. 광범위한 node 프로세스 종료나 실제 데이터 초기화로 해결하지 않는다.
5. 라우팅은 버튼 클릭/새 탭, 직접 주소, 새로고침, fragment, 로그인 전 진입을 확인한다. 안내 페이지는 로그인 없이 열려야 한다.

검사 결과는 이번 실행 기준으로 보고한다. 실제 외부 AI/SSO 검증과 테스트 대체 공급자 검증을 구분하고, 실행하지 못한 항목은 명시한다. 임시 보고서·화면 캡처는 필요한 증거를 남긴 뒤 프로젝트 밖으로 옮기거나 정리한다.
