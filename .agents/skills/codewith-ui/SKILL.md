# UI 기준

## 확정된 디자인

- 기본 강조색은 인디고 `#6260B4`, 라이트 배경은 `#F7F7FB`, 다크 강조색은 `#B7B5F1`이다. 완료·연결 상태의 초록색과 경고·오류색은 의미를 구분한다.
- 색상은 `src/styles/style.css`, `theme.css`, `controls.css`, `vuetify.css`의 기존 토큰과 `src/main.js`의 Vuetify 테마를 함께 확인한다. `--green`은 과거 이름이지만 현재 강조색 토큰이다. 이름만 보고 초록색을 다시 넣지 않는다.
- 로고 원본은 `public/logo.svg`, 탭 아이콘과 공유 HTML 아이콘의 공통 처리는 `public/branding.js`다. 복사한 SVG/base64를 화면별로 고정하지 않는다.
- 공유 파일 버튼은 **공유 아이콘만** 표시한다. `aria-label`과 title은 '공유 파일'로 유지한다. 사용자가 제거한 보이는 문구와 문자 화살표를 되살리지 않는다.
- 워크스페이스 HTML 다운로드는 기본 설정 화면의 워크스페이스 문서 영역에 둔다. 공유 파일 메뉴는 JSON 교환 기능으로 구분하고 HTML 다운로드 버튼을 다시 넣지 않는다. 기존 HTML 재불러오기 호환성은 별도 기능이다.
- 앱 아이콘은 `CwIcon`/`src/services/icons.js`, Vuetify 아이콘은 설정된 SVG iconset을 사용한다. 방향 표시를 폰트 글리프와 pseudo-element로 임시 대체하지 않는다.

## 레이아웃 검토

- 화면·편집 창 전체에 작용하는 삭제·저장·내려받기·연결 등의 작업 버튼은 상단 작업 영역 또는 하단 푸터에 모은다. 입력 본문이나 설명·접힌 상세 영역 뒤에 독립 버튼을 끼워 넣지 않는다. 모달에서는 공통 `headerActions`·`footerStart`를 사용하고 저장·취소와 위치를 일관되게 유지한다. 개별 목록 항목의 편집·삭제나 입력 옆 폴더 선택처럼 대상과 붙어 있어야 의미가 명확한 작업은 해당 항목의 헤더나 같은 줄에 둔다.

- 같은 기능에 속하는 입력·선택·실행 컨트롤은 가능한 한 같은 줄에 묶는다. 예를 들어 경로 입력과 폴더 선택 버튼은 나란히 배치한다. 입력 공간과 버튼 가독성을 확보하고, 좁은 화면에서는 잘림이나 가로 넘침 대신 자연스럽게 줄바꿈한다.

- Vuetify 버튼에는 `.v-btn__content` 래퍼가 있다. 기존 직계 자식 선택자, flex/grid, gap이 실제 DOM에도 적용되는지 확인한다.
- Vuetify density의 고정 높이가 여러 줄 제목·권한·버전 설명을 자르지 않게 한다. 높이 문제를 고치며 선택/hover/dark 색상 우선순위까지 덮어쓰지 않는다.
- 문자열 존재 여부만으로 정상 표시를 판정하지 않는다. 글자의 실제 경계가 버튼·카드 안에 있는지, 줄바꿈·겹침·가로 넘침과 한글 입력을 본다.
- 의미를 충분히 전달할 수 있는 동작은 텍스트보다 아이콘 버튼을 우선한다. 문맥만으로 이해하기 어려운 동작은 텍스트를 유지한다. 아이콘만 있는 버튼에는 `aria-label`과 툴팁 또는 `title`로 동작 이름을 제공한다. 팝업은 열림/닫힘 방향, Escape, 포커스 복귀를 확인한다.
- 라이트/다크, 데스크톱/모바일 중 변경이 영향을 주는 조합을 실제 브라우저와 화면 캡처로 확인한다. 전환 애니메이션 중간 프레임을 깨짐으로 오인하지 않는다.
- 공통 색상 변경은 안내·인증 대기·계획 미리보기·공유 내보내기에 미치는 영향까지 확인한다. 저장된 사용자 계획을 테마 변경만으로 재작성하지 않는다.
