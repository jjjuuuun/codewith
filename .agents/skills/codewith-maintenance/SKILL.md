# 파일과 지침 관리

## 정리·공유

- 삭제 전 import, 서버 정적 경로, 빌드 스크립트, 테스트, 문서에서 참조 여부를 확인한다. 이름만 보고 미사용으로 판단하지 않는다.
- `.codewith/`는 실제 사용자 데이터·인증 정보다. `.env`, 키 파일, 로그인 키 JSON과 함께 커밋·출력·임의 삭제 대상에서 제외한다.
- `dist/`, `node_modules/`, `data/screenshots/`, `data/browser-verification.json`은 재생성 가능한 로컬 산출물이다. Git 제외 여부와 현재 작업에서 쓰는지 구분한다.
- `public/text-editor.js`는 생성물이지만 서버·브라우저가 사용하는 필요한 진입점이다. `local/`, 테스트 fixture, 인증 대기 페이지도 참조를 조사한 뒤 판단한다.
- 지침·스킬은 런타임 파일은 아니지만 앞으로 작업하기 위한 프로젝트 소스다. `AGENTS.md`, `CLAUDE.md`, `.agents/skills/`, `.claude/skills/` 연결은 Git에 포함할 수 있다. 개인 설정·자격 정보와 혼동하지 않는다.
- 불필요한 임시 마이그레이션 스크립트·백업·스크린샷을 루트에 쌓지 않는다. 사용자가 만든 변경은 보존한다.

## 규칙의 단일 원본

- `AGENTS.md`: 작업 범위, 최소 공통 원칙, 상황별 스킬 경로만 둔다.
- `CLAUDE.md`: `@AGENTS.md`를 가져오는 얇은 진입점이다. 스킬 내용을 모두 import하여 매번 불러오지 않는다.
- `.agents/skills/<name>/SKILL.md`: 상황별 규칙의 유일한 원본이다. name/description frontmatter에 적용 대상을 명확히 쓴다.
- `.claude/skills/<name>`: 원본 스킬 디렉터리로 가는 상대 심볼릭 링크다. 내용 복사본을 만들지 않는다.
- 새 스킬 추가 시 AGENTS 목록과 Claude 연결을 함께 추가한다. 링크 환경을 바꿀 때 실제 대상이 동일한지 확인한다.
- 사용자가 명시적으로 확정한 장기 선호는 해당 스킬에 반영한다. 일회성 질문·추측·실험 결과를 영구 규칙으로 확대하지 않는다.
- 현재 프로젝트 구조가 달라지면 관련 스킬과 README를 함께 갱신한다. 모든 세션의 진행 로그·테스트 횟수를 지침에 누적하지 않는다.
- 앱에서 사용하는 기본 스킬은 `skills/defaults/<id>/SKILL.md`가 원본이며 개발 에이전트 지침과 구분한다. 워크스페이스의 MD 사본은 데이터 폴더의 `workspaces/<id>/skills/`에 저장한다. 기존 사용자의 편집 지침을 기본값 갱신으로 덮어쓰지 않는다. 변경 이력의 기준은 DB이며, MD 직접 편집은 웹 가져오기로 적용한다.
- 스킬 변경은 frontmatter, 파일 경로, 상대 링크, 참조 원본 일치를 검증한다. 이 지침이 에이전트나 도구의 실행 권한을 추가로 부여하지는 않는다.
