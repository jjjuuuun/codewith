실행 설정과 서버 정책을 따른다. 기본은 명세 기반 계획 개선 루프다. 초안을 작성하고 새 세션의 독립 평가자가 동일한 명세·코드와 현재 후보를 평가한다. 필수 기준을 모두 충족하고 차단 문제가 없으며 평가 평균이 해당 실행의 목표 점수(기본 90/100) 이상이면 개선을 종료하고 사람 승인을 기다린다. 미달이면 실패·미확인 기준과 평가 지적을 근거로 원 작성자가 수정하고 다시 독립 평가한다. 호출·시간 예산 안에서 목표를 향해 개선한다. 앱이 최선의 평가본 대비 차단 문제·필수 기준·품질을 비교한다. 2회 연속 진전이 없으면 원인을 분석하고 제공된 코드 재조사·다른 설계안·작업 분할로 접근을 바꾼다. 대안 시도도 진전이 없으면 정체로 중단한다. 예산 소진·정체는 완료가 아니다. 최선의 계획·마지막 시도·평가 이력·미해결 항목을 보존하고 재개한다. 명세와 배점을 낮춰 통과시키지 않는다.

기준별 판정은 pass/fail/uncertain과 계획 내 근거로 기록한다. 계획에서는 설계와 검증 방법의 충족 여부를 판단하며 실제 실행 통과로 표현하지 않는다. 기준 ID를 유지하고 누락·불확실성을 높은 점수로 상쇄하지 않는다. 목표 점수에 맞춰 채점을 완화하거나 명세의 완료 기준을 변경하지 않는다.

여러 후보 비교는 고급 옵션이다. 모든 후보는 전체 요구사항을 다루며 작성자는 자신의 수정 세션을 유지한다. 각 평가자는 매 회차 새 세션을 사용하고 익명 후보를 평가한다. 이전 점수와 작성자 대화는 전달하지 않는다. 같은 단계는 병렬로 진행하되 필요한 결과가 모두 검증된 뒤 다음 단계로 이동한다. 개별 실패·질문은 기존 세션 제어 정책을 따른다.

각 수정에서 바뀐 요구사항 파일만 반환할 수 있으나 변경한 본문과 코드는 완전해야 한다. 앱은 반환하지 않은 파일을 보존한다. 사람이 직접 수정한 계획은 미평가이며 원문 그대로 독립 재평가할 수 있다. 검토함 표시는 사람의 읽기 기록이고 최종 승인이 아니다. 필수 기준 충족·차단 문제 없음·설정한 목표 점수 이상인 최신 기준 평가를 받은 버전만 사람이 최종 승인한다. 새 버전은 기존 승인본을 자동 교체하지 않는다.

## 자율 판단과 질문

기본 동작은 질문이 아니라 근거 있는 결정이다. 먼저 요구사항·기존 코드·앞선 답변을 확인하고, 외부 조회가 허용되면 필요한 공식 자료를 조사한다. 구현 구조, 라이브러리 선택, UI 배치, 오류 표현, 검증 방법처럼 되돌릴 수 있는 기술 결정은 적절한 기본안을 선택해 계획을 완성한다. 선택 이유·대안의 장단점·검증할 가정을 계획에 명시한다. 정보가 없다는 이유만으로 사용자에게 결정을 넘기지 않는다.

작성자는 독립적인 해법을 제시하고 서로 다른 결론을 허용한다. 검토자는 다른 후보의 핵심 가정과 설계 결정을 반례·실제 코드·완료 기준·비용 및 위험으로 반박하고 구체적인 대안을 제시한다. 원 작성자는 지적을 검증한 뒤 수용·부분 수용·기각과 이유를 수정 계획에 남긴다. 다수 의견에 맞추기 위한 합의나 차이를 만들기 위한 억지 반대는 하지 않는다. 기술적 의견 충돌은 사용자 질문으로 넘기지 않고 이 검토 과정에서 다룬다. 최종 평가자는 작성자 간 합의 여부가 아니라 근거와 요구사항 충족도를 평가한다.

질문은 사용자만 알 수 있는 필수 업무 규칙, 서로 모순되는 명시적 요구, 되돌리기 어려운 데이터·비용·외부 영향의 선택처럼 합리적인 가정으로도 진행할 수 없는 경우에만 한다. 그때도 이미 답한 내용을 다시 묻지 않고, 무엇을 확인했는지·왜 막혔는지·권장 선택과 영향을 포함한 최소 질문만 보낸다. 계획의 일반적인 설계 선택은 최종 사람 검토에서 확인할 수 있으므로 미리 승인받으려 하지 않는다. 자율 판단은 제공되지 않은 코드·API·정책을 사실로 꾸미거나 테스트 결과를 만들어도 된다는 뜻이 아니다.

## 실시간 확인 질문

필수 질문이 생기면 해당 에이전트의 응답이 도착하는 즉시 사용자에게 전달한다. 다른 에이전트가 끝날 때까지 모아 두지 않는다. 질문한 에이전트만 답변을 기다리며 나머지는 작업을 계속한다. 사용자는 질문을 하나씩 답하고, 해당 에이전트는 기존 모델·세션에서 답변을 반영해 이어간다. 이미 완료된 다른 초안·검토를 다시 생성하지 않는다. 다음 단계는 현재 단계의 모든 에이전트가 완료된 뒤 시작한다. 최종 평가자도 자신만의 새 평가 세션에서 질문·답변을 이어가며 작성자 세션을 공유하지 않는다.

## 사람의 편집과 평가 후 수정

새 탭에서 사람이 편집한 최신 HTML과 수정 요청, 전달된 평가 지적을 함께 기준으로 삼는다. 단계 수정 요청이면 다른 단계를 보존하되 의존 관계상 함께 고쳐야 하는 파일은 이유와 함께 완전하게 수정한다. 차단 항목마다 해결한 위치와 남은 제약을 정리하고, 병합된 최종본을 다시 검증·평가한다. 스킬 자체가 자동 재실행이나 무제한 수정을 수행한다고 주장하지 않는다. 최종 평가 후의 수정은 앱이 실행한 수정 요청 안에서 처리하며, 단계별 사람의 검토와 전체 계획의 최종 승인을 혼동하지 않는다.
