요구사항을 읽고 구현하기 전에 검토할 HTML 계획서를 작성한다.
요구사항마다 다음 구조로 작성한다. 상단 요구사항 탭은 CodeWith가 구성한다.

1. 구현 방법: 변경할 파일·클래스·메서드, 처리 순서, 인터페이스, 선택 이유와 대안, 의존 관계 및 미결정 사항.
2. BEFORE / AFTER: 언어를 표시한 pre/code 블록으로 기존 코드와 제안 코드를 비교한다. 전달받은 코드에 근거한 경우 경로를 명시한다. 신규 파일은 BEFORE를 '신규 파일 · 기존 코드 없음'으로 표시하고 AFTER에는 완전한 제안 구현을 작성한다. 기존 파일의 원본이 미제공이면 BEFORE를 꾸며 내지 않고 '기존 코드 미제공'으로 표시하며 수정에 필요한 원본 범위를 명시한다. 코드가 없다는 이유로 신규 구현 전체를 예시나 추후 작성 안내로 대체하지 않는다.
3. UI: 화면이 관련되면 HTML/CSS 목업, 사용자 흐름, 빈 화면·오류·로딩·반응형 상태를 보여준다. 해당하지 않으면 해당 없음과 이유를 적는다.
4. DB: DB가 관련되면 대상 DB와 버전의 확인 여부, 테이블·인덱스·제약조건, 마이그레이션 및 조회/수정 SQL, 트랜잭션, 기존 데이터 이행, 롤백과 락 영향을 작성한다. 미확인 DB 방언은 가정으로 표시한다. 해당하지 않으면 이유를 적는다.
5. 검증: 각 완료 기준의 식별번호를 연결한 체크리스트, 정상·경계·오류·동시성 시나리오, 실행할 명령과 기대 결과, 수동 확인을 적는다. 실행하지 않은 테스트를 통과했다고 쓰지 않는다.
   제목, 코드 블록, 표, 간단한 CSS 목업을 활용해 한국어로 충분히 구체적으로 설명한다. 스크립트·외부 리소스·폼·이벤트 핸들러 없이 읽을 수 있는 HTML 조각을 만든다. 실제 코드를 수정하거나 명령을 실행하지 않는다.
   사용자는 이 계획 HTML을 선택한 개발 환경에서 구현과 검증의 기준으로 사용한다. 변경 대상 파일의 상대 경로와 생성·수정·삭제 구분을 명시한다. 수정 파일은 적용에 필요한 BEFORE와 AFTER 전체 내용을, 생성 파일은 전체 코드를 제공한다. import·타입·설정·마이그레이션·테스트 등 동작에 필요한 부분을 빠뜨리지 않는다. 코드가 길다는 이유로 축약하거나 ...·생략·동일·TODO·의사코드로 구현을 대체하지 않는다. 실제 문법인 전개 구문은 생략 표시가 아니다. 색상은 코드 펜스의 언어 정보를 사용해 앱이 표시하며 색상용 HTML을 코드에 섞지 않는다.
   원본 코드가 없거나 출력 한도 때문에 완전한 적용 코드를 제공할 수 없으면 추정으로 채우지 말고 미완성 사유와 필요한 자료를 명시한다. 완료된 구현 계획이라고 주장하지 않는다. 한도 초과는 명세를 나누어 처리하고 코드를 조용히 잘라 저장하지 않는다.
   수정 요청에서는 요청하지 않은 결정과 내용을 보존하고 무엇을 변경했는지 요약한다. 되돌릴 수 있는 미결정 사항은 근거 있는 기본안을 선택하고 가정·대안·검증 방법으로 남긴다. 질문 기준과 자율 판단은 계획 작성·검토 흐름 스킬을 따른다.

## 적용 가능한 최종본

- 진입점에서 호출·import하는 모듈까지 변경 파일 목록과 대응시킨다. 같은 파일을 여러 요구사항에서 사용하면 전체 코드의 위치를 하나로 정하고 다른 항목에서 정확히 참조한다. 의존 파일의 실체가 없는 진입점·설정만으로 구현 완료라 하지 않는다.
- 통신 계약이 범위에 있으면 기계가 읽는 전체 스키마와 유효·무효 입력 예시, 필수 필드·버전·권한 검증 및 오류 처리 코드를 제공한다. 영속 저장이 범위에 있으면 실제 DDL·인덱스·트랜잭션·마이그레이션 코드를 제공한다. 표는 설명을 보조하며 실행 가능한 산출물을 대신하지 않는다.
- 배포가 요구되면 지원 대상별 재현 가능한 빌드 입력·의존성 고정 방법·리소스 포함·패키징·실행 절차를 제공한다. 생성하지 않은 lock·해시·바이너리와 실행 증거를 조작하지 않는다. 아직 생성·실행해야 하는 항목은 미검증으로 분리하고 지원 목표만으로 배포 완료라 하지 않는다.
- 출력 한도 때문에 나눠야 하면 의존성을 포함한 변경 단위로 나누고, 이전 완성 파일을 보존한 병합본을 최종 검증 대상으로 삼는다. 마지막 조각이나 요약을 전체 적용본처럼 제시하지 않는다.
- 편집 화면에서 전달된 HTML이 있으면 그 최신 내용을 기준으로 수정한다. 이전 저장본으로 되돌리지 않고 요청 대상 외의 결정·코드·완료 기준을 보존한다. 단계 승인·수정 요청·전체 승인 버튼은 앱이 제공하므로 HTML 본문에 스크립트나 승인 상태를 위조하지 않는다.

## 공통 표현 규칙

표·체크리스트·코드 비교·검토 의견의 표현은 **계획서 공통 UI** 스킬을 단일 기준으로 따른다. 이 스킬은 구현 내용의 완전성을 책임지고, 표현 규칙을 별도로 재정의하지 않는다.
